# A09 · 自动化与闭环评分标准

> sub-agent 评分用。**不写代码、不讲怎么做**——只给**与本项目审美基准的匹配度评分**。
> 本项目的审美基准：**A 评分必须自动跑、A→B→A 闭环必须真闭环、不靠人工盯**。
> 加载本 ref 前必读 [[A00-审核总纲]]。

## 评分目标

评估面板（及其相关流水线）的**自动化与闭环程度**与本项目审美基准的匹配度——A 评分能否自动触发、A→B→A 闭环能否真跑通、不达标能否自动阻断。

## 评分维度（每项 0-5）

### 1. A 评分自动化程度（权重 2）
- A01~A08 评分脚本是否纳入 CI
- 是否有手工跑一次的「假自动化」
- 失败时是否阻断合入

### 2. lint / e2e / no-emoji 自动化（权重 1）
- lint、e2e、no-emoji、build 是否全部纳入 CI
- 是否构成「跑 lint → 跑 A 评分 → 跑 e2e → build」的串联

### 3. A→B→A 闭环真实度（权重 2）
- A 不达标时是否自动回到 B（修复）
- B 实现完成后是否自动回到 A（验收）
- 是否避免「写完 A 评分但流程上是单向的」

### 4. 异常回流（权重 1）
- 用户报错 / 测试失败 / A 评分 C-D-F 是否回流到 issue / backlog
- 是否有人工参与的「断点」让闭环中断

### 5. 可观测性（权重 1）
- A 评分历史是否有存档
- 失败时是否有截图 / 日志 / 报告可查

## 评分标准（绝对严格）

### S 级（5 分）
- A 评分 + lint + e2e + no-emoji 全部纳入 CI，失败自动阻断
- A→B→A 闭环全自动（A 评分 C/D/F → 自动 issue → 主 agent 修复 → 再跑 A → 通过）
- 异常回流 + 可观测性齐备
- **完全匹配本项目审美基准**

### A 级（4 分）
- 满足 S 级全部条件，仅小缺（如缺可观测性）
- **整体匹配**

### B 级（3 分）
- 主流程纳入 CI，但 A 评分自动化缺失
- **基本匹配**

### C 级（2 分，必须修复）
- A 评分脚本存在但未纳入 CI（手工跑）
- **明显偏离**

### D 级（1 分，拒绝通过）
- 「写完代码只跑 build」就算交付
- **完全背离本项目审美基准**

### F 级（0 分，拒绝通过）
- 没有任何自动化机制
- **闭环根本不存在**

## 评分依据（命中即扣分）

| 偏离项 | 扣分依据 |
| --- | --- |
| 写完代码只跑 build 就交付 | 闭环第一步就缺 |
| A 评分脚本存在但未纳入 CI | 手工跑 = 不算自动化 |
| A 不达标时只警告不阻断 | 闭环第二步就崩 |
| B 实现完成后没有再跑 A | 闭环没有回到 A |
| 用户报错 / 测试失败无回流 | 闭环外部断点 |
| A 评分历史无存档 | 可观测性缺 |
| 没有截图 / 日志 | 出问题无据可查 |
| 异常路径未覆盖 | 异常无回流 |
| 流水线分支保护缺失 | 失败也能合入 |

## 评分报告模板

参见 [[A00-审核总纲]]「输出报告模板」一节，按以下顺序输出：

1. 与本项目审美基准的匹配度
2. A 评分自动化程度评分
3. lint / e2e / no-emoji 自动化评分
4. A→B→A 闭环真实度评分
5. 异常回流评分
6. 可观测性评分
7. 垃圾 UI/UX 命中清单
8. 总分、结论

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A09）确定评分维度
2. 打开 CI 配置（`.github/workflows/` / `.gitlab-ci.yml` / Jenkinsfile）
3. 检查流水线步骤：
   - 是否跑 lint？
   - 是否跑 no-emoji？
   - 是否跑 A 评分脚本？
   - 是否跑 e2e？
   - 是否跑 build？
   - 失败时是否阻断合入？
4. 检查 A→B→A 闭环：
   - A 评分脚本是否被 main agent 在「实现完成后」自动调用？
   - 不达标时是否自动回到 B？
5. 检查异常回流：
   - A 评分 C/D/F 是否自动创建 issue？
   - 用户报错是否有回流渠道？
6. 检查可观测性：
   - A 评分历史是否存档？
   - 失败时是否有截图 / 日志？
7. 按评分标准套等级
8. 输出报告

## 反 AI-default：评分自动化时的常见错误

| AI 默认行为 | 后果 | 正确做法 |
| --- | --- | --- |
| 「我跑过一次 A 评分」就算自动化 | 改完代码后还得手工跑 | 纳入 CI 自动触发 |
| 失败时只警告不阻断 | 失败也能合入 | 失败 = 阻断 |
| B 写完没人回头 A | 闭环没回到 A | 主 agent 流程强制回头 A |
| 没存档 | 出问题无据可查 | A 评分历史存档 |
| 异常无回流 | 用户报错丢了 | 失败 → 自动 issue |
| 流水线分支保护缺失 | 失败也能合入 | 必需检查 |
