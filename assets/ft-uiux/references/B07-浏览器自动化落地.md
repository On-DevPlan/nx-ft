# B07 · 浏览器自动化落地（真点验证）

> 对应 A07 评分维度。**主 agent 落地实现**——给「按钮真点验证」的具体模式骨架。
> 加载本 ref 前必读 [[B00-实现总纲]] 与 [[A07-浏览器自动化评分]]。
>
> **本 ref 讲思想与模式，不绑定特定框架**——
> playwright / cypress / selenium 等任何浏览器自动化工具都能套用。

## 实现目标

把 [[A07-浏览器自动化评分]] 要求的**真点覆盖 + 返回值核验 + 截图存档 + CI 集成**落地为可执行的自动化脚本。

## 模式骨架

### 单按钮真点验证（伪代码）

```
1. 启动应用 + 进入目标页面
   goto(目标 URL, waitUntil=networkidle)

2. 找到按钮（按角色 / 文本 / testid 三选一）
   btn = getByRole('button', name=<按钮文案>)
        或 getByTestId(<testid>)

3. 记录点击前状态（用于核验返回值）
   before = count(<列表区>)

4. 真点
   btn.click()

5. 等待响应 + 核验 DOM 变化
   waitForResponse(url 包含 /api/<module>, status=200)
   expect(count(<列表区>) = before + 1)

6. 截图存档
   screenshot(path=screenshots/<module>-<action>.png)
```

### 选择器策略（关键）

```
优先级（稳 → 脆）：
  1. role + name           getByRole('button', name)
  2. testid                getByTestId(<id>)
  3. aria-label            getByLabelText(<label>)
  4. label text            getByText(<text>)
  ✗ nth-child(3)          改 view 后测试全红
  ✗ ul > li:first         同上
  ✗ className             同上
```

> **核心**：选择器必须**稳定且语义化**——
> 写 view 时就要给关键元素加 `data-testid` 或 `role` / `aria-label`，
> 让测试脚本能稳定定位。

### 跨按钮的真点覆盖

```
遍历所有按钮（BUTTONS = [...]）：
  for { name, action } in BUTTONS:
    test(`${action}: 真点验证`):
      goto(目标 URL)
      btn = getByRole('button', name).first
      expect(btn).toBeVisible
      btn.click()
      waitForLoadState(networkidle)
      # 按 action 不同核验返回值
      screenshot
```

### 异常路径覆盖

```
异常 1：按钮被遮挡
  - 注入遮挡层
  - expect(btn).toBeDisabled / toBeHidden

异常 2：异步接口失败
  - route(/api/<module>) → fulfill(500)
  - 触发按钮
  - expect(toast).toContainText(/失败|错误/)

异常 3：异步超时
  - 故意 sleep > timeout
  - expect(loading 态持续)

异常 4：onClick 漏绑
  - 触发按钮
  - expect(接口被调用次数).toBe(0)  ← 漏绑就抓到了
```

## 关键 props / state（脚本侧）

| 项 | 取值 | 备注 |
| --- | --- | --- |
| `goto(url)` | 必须用 `127.0.0.1` 而非 `localhost` | IPv6 / IPv4 解析差异 |
| `waitForLoadState` | `networkidle` 或 `domcontentloaded` | 看场景选 |
| `waitForResponse` | 必须有——否则点完就跑了 | 真点的核心 |
| `expect(...).toHaveCount(...)` | DOM 变化核验 | 比 `textContent` 稳 |
| `screenshot` | 每次真点后必拍 | 出问题有据可查 |

## 框架映射（任意 UI 框架适用）

| 概念 | 实现要点 |
| --- | --- |
| 浏览器自动化工具 | playwright / cypress / selenium 任选；本项目偏好 playwright |
| 选择器 | `role` / `testid` / `aria-label` 三类，不依赖框架语法 |
| 网络拦截 | `page.route(url, handler)`（playwright）/ `cy.intercept()`（cypress） |
| CI 集成 | 任何 CI 都能跑（GitHub Actions / GitLab CI / Jenkins） |

## 与 A 评分标准的对照表（反向验证）

## 测试要点

- [ ] 每个按钮都有 .spec，主操作 + 边界情况都覆盖
- [ ] 每次真点后都有 waitForResponse + DOM 核验
- [ ] 每次真点后都有截图存档
- [ ] 至少 3 个异常路径测试（按钮被遮挡 / 接口失败 / 异步超时）
- [ ] 全部跑通纳入 pnpm test 总链
- [ ] CI 流水线真跑（不是人工跑一次）
- [ ] 失败时阻断合入（保护分支 / 必需检查）

## 反模式

| 错误做法 | 后果 | 正确做法 |
| --- | --- | --- |
| 用 nth-child(3) 选元素 | 改 view 后测试全红 | getByRole / testid / aria-label |
| 不 waitForResponse | 点击事件还没完成就核验了 | 必加 waitForResponse |
| 不截图 | 出问题无据可查 | 每次真点必拍 |
| 只点主操作 | 边界情况没覆盖 | 遍历所有按钮 + 异常路径 |
| 不纳入 CI | 改完代码不一定重新跑 | 纳入 pnpm test |
| 用 localhost 而非 127.0.0.1 | Node 18+ IPv6 解析差异 | 用 127.0.0.1 |
| 单元测试覆盖了逻辑就交付 | 单元测试不会真去点按钮 | 真点验证是**唯一**验证 |
| 锁定单一自动化工具 | 换工具就要重写 | 模式通用（playwright/cypress/selenium 都行） |
