# A08 · 一致性与无 emoji 评分标准

> sub-agent 评分用。**不写代码、不讲怎么做**——只给**与本项目审美基准的匹配度评分**。
> 本项目的审美基准：**图标走 SVG + 无 emoji + 跨模块一致 + 跨主题一致**。
> 加载本 ref 前必读 [[A00-审核总纲]]。

## 评分目标

评估面板的**视觉一致性**与本项目审美基准的匹配度——一致性是「多模块拼起来像同一个产品」的基础。

## 评分维度（每项 0-5）

### 1. 无 emoji 匹配度（权重 2）
- 全文是否搜不到任何 emoji 字符
- 按钮文案、状态标签、装饰是否含 emoji

### 2. 图标走 SVG 匹配度（权重 2）
- 所有图标是否走 SVG（详见 [`ft-svg`](../ft-svg/SKILL.md)）
- 是否混用 emoji / 字符 / 图片

### 3. 跨模块一致度（权重 2）
- `html` 模块 / `svg` 模块 / 未来 `<X>` 模块的视觉是否一致
- 同样的按钮是否长得一样（如「+ 新建」按钮）

### 4. 跨主题一致度（权重 1）
- 浅色 / 深色主题下，主色 / 危险色 / 字号 / 行高是否一致
- 主题切换是否平滑

### 5. 命名 / 文案一致度（权重 1）
- 同样的概念是否用同样的词（如「新建」vs「创建」混用）
- 状态标签是否统一（如「已保存」vs「保存成功」混用）

## 评分标准（绝对严格）

### S 级（5 分）
- 无 emoji + 图标走 SVG + 跨模块一致 + 跨主题一致 + 文案一致
- **完全匹配本项目审美基准**

### A 级（4 分）
- 满足 S 级全部条件，仅小缺（如某模块文案略不同）
- **整体匹配**

### B 级（3 分）
- 主模块一致，但次要模块偏离
- **基本匹配**

### C 级（2 分，必须修复）
- 出现 emoji 字符
- 跨模块视觉明显不一致
- **明显偏离**

### D 级（1 分，拒绝通过）
- 多处 emoji + 图标混用 + 跨模块视觉割裂
- **完全背离本项目审美基准**

### F 级（0 分，拒绝通过）
- 整个产品看起来像多个产品拼接
- **一致性崩坏**

## 评分依据（命中即扣分）

| 偏离项 | 扣分依据 |
| --- | --- |
| 按钮文案含 emoji（✓ / ⚠ / 🚀） | 跨平台渲染不一致 |
| 状态标签含 emoji（🚧 进行中 / ❌ 失败） | 同上 |
| 装饰含 emoji（任何表情字符） | 同上 |
| 图标混用 emoji / 字符 / 图片 | 视觉割裂 |
| `html` 模块和 `svg` 模块按钮长得不一样 | 跨模块不一致 |
| 同样的概念用不同的词（「新建」vs「创建」） | 文案割裂 |
| 浅色 / 深色主题下主色不同 | 主题不一致 |
| 浅色 / 深色主题下字号不同 | 同上 |
| 状态标签用词不统一（「已保存」vs「保存成功」） | 同上 |
| 跨模块行高不一致（28 vs 36） | 视觉割裂 |

## 评分报告模板

参见 [[A00-审核总纲]]「输出报告模板」一节，按以下顺序输出：

1. 与本项目审美基准的匹配度
2. 无 emoji 匹配度评分
3. 图标走 SVG 匹配度评分
4. 跨模块一致度评分
5. 跨主题一致度评分
6. 命名 / 文案一致度评分
7. 垃圾 UI/UX 命中清单
8. 总分、结论

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A08）确定评分维度
2. 打开所有相关模块的 view.jsx + 截图
3. 与本项目审美基准做**对照评分**：
   - emoji 正则 `[\u{1F300}-\u{1FAFF}]`：命中即 D
   - 图标来源：是 SVG？emoji？图片？
   - 跨模块对照：同样的按钮长得一样吗？
   - 跨主题对照：浅色 / 深色下主色 / 字号一致吗？
   - 文案对照：同样的概念用同样的词吗？
4. 按评分标准套等级
5. 输出报告
