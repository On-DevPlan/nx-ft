# A03 · CRUD 完备性评分标准

> sub-agent 评分用。**不写代码、不讲怎么做**——只给**与本项目审美基准的匹配度评分**。
> 本项目的审美基准：**完整 CRUD + 查询入口齐备 + URL 同步**——缺一个端点视为残缺。
> 加载本 ref 前必读 [[A00-审核总纲]]。

## 评分目标

评估面板是否**把完整的 CRUD + 查询能力**全部暴露给 Web 用户——与「本项目追求 100+ 资源管理能力」这一基准的匹配度。

## 评分维度（每项 0-5）

### 1. 五端点齐备度（权重 3）
- list / get / create / update / delete 是否全部暴露给 Web

### 2. 查询入口齐备度（权重 2）
- 关键字搜索 / 标签筛选 / 排序 / 分页 是否全部暴露

### 3. 表单校验完善度（权重 1）
- 必填项是否校验
- 重复名是否给警告（不直接拒绝）
- 非法字符是否前端提示

### 4. 删除确认完善度（权重 1）
- 单条删除是否二次确认
- 非空资源是否提示影响范围

### 5. URL 状态同步度（权重 2）
- 视图状态（搜索 / 标签 / 排序 / 分页 / 已选）是否全部落到 URL

## 评分标准（绝对严格）

### S 级（5 分）
- 五端点 + 查询入口 + URL 同步全部到位
- 表单校验完善（必填 / 重复名 / 非法字符都有反馈）
- 删除二次确认 + 非空资源影响范围提示
- **完全匹配本项目审美基准**

### A 级（4 分）
- 五端点齐，但查询入口不全（如缺排序）
- **整体匹配，仅小缺**

### B 级（3 分）
- 缺一个端点（如不能 update）
- **基本匹配，但违反核心原则**

### C 级（2 分，必须修复）
- 缺两个端点
- **明显偏离本项目审美基准**

### D 级（1 分，拒绝通过）
- 缺 update 或 delete
- **残缺模块，禁止上线**

### F 级（0 分，拒绝通过）
- 完全没有 create 或 list
- **模块无法使用**

## 评分依据（命中即扣分）

| 偏离项 | 扣分依据 |
| --- | --- |
| 没有 update 端点（只能删了重建） | 残缺模块 |
| 没有 delete 端点 | 残缺模块 |
| 列表只支持全量，没有搜索 / 标签筛选 | 100+ 资源找不回来 |
| 视图状态只放内存（刷新就丢） | 不能分享链接 |
| 删除无二次确认 | 误删无法挽回 |
| 必填项无校验 | 服务端兜底用户才知道 |
| 提交后留在原表单 + 弹「已保存」 | 用户不知道发生了什么 |
| 重复名不警告直接提交 | 用户操作无反馈 |
| 非法字符不提示直接报错 | 用户不知道为什么失败 |
| 没有排序功能 | 默认排序可能不对 |
| 没有分页（100+ 资源全量加载） | 性能问题 |
| 非空资源删除不提示影响范围 | 静默删子资源 |
| 列表只展示名 + 一个字段 | 其余字段返回了但不展示 |
| 表单提交后不跳转 | 用户不知道发生了什么 |

## 评分报告模板

参见 [[A00-审核总纲]]「输出报告模板」一节，按以下顺序输出：

1. 与本项目审美基准的匹配度
2. 五端点齐备度评分（含每个端点的存在性）
3. 查询入口齐备度评分
4. 表单校验完善度评分
5. 删除确认完善度评分
6. URL 状态同步度评分
7. 垃圾 UI/UX 命中清单
8. 总分、结论

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A03）确定评分维度
2. 打开资源模块的 view.jsx + service.js
3. 列出该模块所有可调用端点（从 routes --json 取）
4. 比对五端点是否全部在 view.jsx 被调用
5. 比对查询入口是否全部暴露
6. 检查 URL 参数（搜索 / 标签 / 排序 / 分页）
7. 检查表单校验（必填 / 重复名 / 非法字符）
8. 检查删除确认（二次确认条存在？）
9. 按评分标准套等级
10. 输出报告
