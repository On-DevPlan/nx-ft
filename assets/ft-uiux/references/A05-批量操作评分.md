# A05 · 批量操作稳定性评分标准

> sub-agent 评分用。**不写代码、不讲怎么做**——只给**与本项目审美基准的匹配度评分**。
> 本项目的审美基准：**多选 + 全选 + 三态切换不崩 + 跨页保留 + 按钮永远在**。
> 加载本 ref 前必读 [[A00-审核总纲]]。

## 评分目标

评估面板的**批量操作能力**与本项目审美基准的匹配度——批量是 100+ 资源管理能力的核心入口，**稳定性是底线**。

## 评分维度（每项 0-5）

### 1. 多选 / 全选覆盖度（权重 2）
- 是否有「全选当前页」「全选全部」「反选」「取消全选」四个入口

### 2. 三态切换稳定性（权重 2）
- 未选 / 部分选中 / 全选 三态切换时按钮是否永远在
- 是否永远不崩、不消失

### 3. 跨页保留（权重 2）
- 翻页后已选项是否保留
- 切换过滤条件后已选项是否保留
- 退出批量模式后是否清空已选

### 4. 按钮稳定性（权重 1）
- 已选 = 0 时按钮是否禁用
- 操作过程中是否加载态防重复提交
- 操作完成后是否给结果反馈 + 自动清空已选

### 5. 危险操作二次确认（权重 1）
- 批量删除是否二次确认
- 是否输入校验（如输入 `DELETE`）

## 评分标准（绝对严格）

### S 级（5 分）
- 多选 / 全选 / 三态切换 / 跨页保留 / 危险确认全部到位
- **完全匹配本项目审美基准**

### A 级（4 分）
- 满足 S 级全部条件，仅小缺（如缺反选）
- **整体匹配**

### B 级（3 分）
- 多选 / 全选有，但三态切换有崩的情况
- **基本匹配，但稳定性有瑕疵**

### C 级（2 分，必须修复）
- 翻页后已选项全丢
- 批量删除无二次确认
- **明显偏离**

### D 级（1 分，拒绝通过）
- 「全选」按钮点了没反应 / 翻页就丢
- **完全背离本项目审美基准**

### F 级（0 分，拒绝通过）
- 批量操作根本不可用
- **核心功能缺失**

## 评分依据（命中即扣分）

| 偏离项 | 扣分依据 |
| --- | --- |
| 翻页后已选项全丢 | 用户选了几十项，一翻页全没了 |
| 「全选」= 只选当前页，且无跨页入口 | 选了几十项翻页就丢 |
| 「批量 X」按钮点了没反应 | 用户重复点，结果未更新 |
| 删除无确认 | 误点删除无法挽回 |
| 批量条上的按钮会「消失」 | 部分选中时按钮不见了 |
| 批量条和单条「删除」按钮共存 | 用户可能点错 |
| 退出批量模式后已选项仍残留 | 下次进入还显示已选 |
| 用 emoji 标批量按钮 | 跨平台渲染不一致 |
| 操作过程按钮可重复点击 | 重复提交 |
| 操作完成后无结果反馈 | 用户不知道发生了什么 |

## 评分报告模板

参见 [[A00-审核总纲]]「输出报告模板」一节，按以下顺序输出：

1. 与本项目审美基准的匹配度
2. 多选 / 全选覆盖度评分
3. 三态切换稳定性评分
4. 跨页保留评分
5. 按钮稳定性评分
6. 危险操作二次确认评分
7. 垃圾 UI/UX 命中清单
8. 总分、结论

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A05）确定评分维度
2. 打开目标模块的批量操作 UI
3. 与本项目审美基准做**对照评分**：
   - 「全选 / 反选 / 取消 / 已选计数 / 批量 X」五项是否齐？
   - 翻页后已选项是否保留？
   - 三态切换时按钮是否永远在？
   - 批量删除是否有二次确认？
4. 按评分标准套等级
5. 输出报告
