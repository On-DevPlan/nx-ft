# A00 · 审核总纲与评分体系

> 这是 sub-agent 审核的**入口**。
> 加载 A01~A08 的具体评分标准前必读——它规定**本项目的审美基准、评分维度、等级体系**。

## 本项目的审美基准（绝对锚点）

> **GitHub 仓库页**——一个主色点睛、一处留白撑层级、一条灰线分块，
> 没有任何多余的纯色块与 emoji 装饰。

不论哪个模块（`html` / `svg` / 未来的 `<X>`）的 view.jsx，
都得按这一份匹配——**不匹配就是垃圾 UI/UX**，不存在「还行 / 能接受」。

## 评分等级（绝对严格）

| 等级 | 分值 | 含义 | 处置 |
| --- | --- | --- | --- |
| **S** | 5 | 完全匹配本项目审美，可作为参考实现 | 直接通过 |
| **A** | 4 | 匹配本项目审美，达到标准 | 直接通过 |
| **B** | 3 | 基本匹配，但有明显偏离 | 记录到「建议」清单 |
| **C** | 2 | 不匹配，违反核心审美基准 | 必须修复，列入「阻塞」 |
| **D** | 1 | 严重不匹配，必须重做 | **拒绝通过** |
| **F** | 0 | 垃圾 UI/UX，完全背离项目审美 | **拒绝通过 + 标记** |

> **不存在「还行 / 凑合 / 可以接受」**——只要不匹配就是 C 或以下。

## 输出报告模板（每个 A0X 都按这个输出）

```markdown
## A0X · <维度名> 评分报告

**评分对象**：<文件路径 / 模块名 / 组件名>
**评分时间**：<YYYY-MM-DD>
**评分 agent**：<agent 名>

### 与项目审美的匹配度
- 匹配「……基准」：是 / 否（依据）
- 偏离「……基准」：N 处（具体位置）

### 评分（0-5）
- 细项 1：N 分（依据）
- 细项 2：N 分（依据）
- …
- **总分**：N.N 分 → 等级 X

### 评分标准命中清单
- 命中 S 级「……」：N 处
- 命中 A 级「……」：N 处
- 命中 B 级「……」：N 处
- 命中 C 级「……」：N 处（必须修复）
- 命中 D/F 级「……」：N 处（拒绝通过）

### 垃圾 UI/UX 命中清单（绝对严格）
1. `<文件路径>:<行号>` —— 偏离「……基准」—— 必须重做
2. ……

### 结论
- [ ] 通过（A 及以上）
- [ ] 阻塞（C 必须修复）
- [ ] 拒绝（D/F 必须重做）
```

## 通用反例库（命中即扣分）

| 反例 | 扣分 |
| --- | --- |
| 页面里出现 emoji 字符 | D |
| 大面积彩色背景 / 渐变 / 阴影装饰 | D |
| 面包屑放在右上角或不放 | D |
| 翻页后已选项全丢 | D |
| 「全选」按钮点了没反应 / 翻页就丢 | D |
| 详情页 / 编辑页没面包屑 | D |
| 视图状态（搜索 / 标签 / 排序）只放内存不落 URL | D |
| 弹窗里塞大预览 / 多风格对比 / 表单 | D |
| 写完 view.jsx 只跑 build 就交付 | D |
| 卡片列表 + 固定宽度栏（无拖拽） | C |
| 字号跳跃（11/13/15/18 混用） | C |
| 颜色爆炸（成功绿失败红警告黄待办蓝） | C |
| 阴影 / 高光装饰 | C |
| 删除无二次确认 | C |
| 必填项无校验 | C |
| 重复名不警告直接提交 | C |
| 提交后留在原表单 + 弹「已保存」 | C |
| 加载中无法取消 / 按钮闪烁 | C |

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A00）确定评分维度与等级
2. 按需加载 A01~A08 的具体评分标准
3. 对每个评分对象跑一遍所有相关 A0X
4. 输出报告（套上面的模板）
5. 把 D/F 项标红，列入「拒绝通过」清单
6. 把 C 项列入「阻塞」清单，必须修复

> **绝对严格**：不因为「时间紧」「已经做了」就放水——垃圾 UI/UX 就是垃圾。
> 评分不是找亮点，是**找偏离**。没找到偏离不代表满分，代表**这次没看到**——下次还要再看。

## 反 AI-default：AI 给面板打分时的常见错误

| AI 默认行为 | 后果 | 正确做法 |
| --- | --- | --- |
| 看一眼说「整体不错」就给 A | 把违规漏掉 | 必须按 A01~A08 逐条对照 |
| 因为「功能能用」就给高分 | UI/UX 烂 ≠ 功能烂 | UI/UX 烂就是 D |
| 用「还行 / 可以接受」这种话 | 评分不严格 | 只用 S/A/B/C/D/F 六档 |
| 找不到违规就给满分 | 「这次没看到」≠「满分」 | 没违规给 A，有违规给对应档 |
| 把实现细节当 UI/UX 打分 | 跑题 | UI/UX 只评**审美与体验匹配**，不管代码怎么写 |
| 按通用 web 标准打分而非项目标准 | 偏离项目审美 | 永远以 GitHub 仓库页为锚 |
