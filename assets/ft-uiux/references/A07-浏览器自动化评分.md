# A07 · 浏览器自动化真实点击验证评分标准

> sub-agent 评分用。**不写代码、不讲怎么做**——只给**与本项目审美基准的匹配度评分**。
> 本项目的审美基准：**Web 操作必须经 playwright 真点验证，不靠肉眼 / 单元测试**。
> 加载本 ref 前必读 [[A00-审核总纲]]。

## 评分目标

评估面板的**操作是否经真实点击验证**——这是本项目「绝不允许写完代码只跑 build 就交付」的核心审美。

## 评分维度（每项 0-5）

### 1. 真点覆盖度（权重 3）
- 全部按钮是否经 playwright 真点过
- 是否包含主操作 + 边界情况（翻页 / 已选 / 删除）

### 2. 返回值核验（权重 2）
- 点击后是否核验接口返回值 / DOM 变化
- 是否截图存档

### 3. 异常路径覆盖（权重 1）
- 按钮被遮挡 / 异步失败 / onClick 漏绑是否被发现
- 是否有「点不动 / 点错位置」的反例

### 4. 持续集成度（权重 1）
- 真点验证是否纳入 CI（不是人工跑一次）
- 失败时是否阻断合入

## 评分标准（绝对严格）

### S 级（5 分）
- 全部按钮真点 + 返回值核验 + 截图存档 + 异常路径覆盖 + 纳入 CI
- **完全匹配本项目审美基准**

### A 级（4 分）
- 全部按钮真点 + 返回值核验 + 截图存档，但 CI 集成缺失
- **整体匹配**

### B 级（3 分）
- 主操作真点过，但边界情况未覆盖
- **基本匹配**

### C 级（2 分，必须修复）
- 仅手动跑过一次（无自动化）
- **明显偏离**

### D 级（1 分，拒绝通过）
- 写完 view.jsx 只跑 build 就交付
- **完全背离本项目审美基准**

### F 级（0 分，拒绝通过）
- 没有真点验证，按钮根本不知道能不能用
- **核心验证缺失**

## 评分依据（命中即扣分）

| 偏离项 | 扣分依据 |
| --- | --- |
| 写完 view.jsx 只跑 build 就交付 | onClick 漏绑 / 按钮被遮挡都抓不到 |
| 仅手动跑过一次（无自动化脚本） | 改完代码后又得重新跑 |
| 只点主操作按钮 | 批量 / 翻页 / 边界情况没覆盖 |
| 没截图 | 出问题无据可查 |
| 异常路径未覆盖 | 按钮被遮挡 / 异步失败发现不了 |
| 真点验证未纳入 CI | 改完代码不一定重新跑 |
| 用 grep「能找到 onClick」就算验证通过 | 「找到了」≠「能点」 |
| 单元测试覆盖了逻辑就交付 | 单元测试不会真去点按钮 |

## 评分报告模板

参见 [[A00-审核总纲]]「输出报告模板」一节，按以下顺序输出：

1. 与本项目审美基准的匹配度
2. 真点覆盖度评分（含每个按钮的真点状态）
3. 返回值核验评分
4. 异常路径覆盖评分
5. 持续集成度评分
6. 垃圾 UI/UX 命中清单
7. 总分、结论

## 评分 SOP（sub-agent 工作流）

1. 加载本 ref（A07）确定评分维度
2. 打开目标模块的 view.jsx，列出全部交互按钮
3. 检查是否有 playwright 真点脚本：
   - 是否覆盖全部按钮？
   - 是否核验返回值？
   - 是否截图？
   - 是否覆盖异常路径？
   - 是否纳入 CI？
4. 按评分标准套等级
5. 输出报告

> **关键**：本评分标准是**所有 A 维度中唯一涉及代码的维度**——
> 但评的是**「是否经真点验证」**，不是「代码怎么写」。
> 具体实现细节见 [[B01-浏览器自动化落地]]（实现参考）。
