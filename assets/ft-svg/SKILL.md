# ft-svg skill：SVG 资源的规范与协作层

这是 [`nx-ft`](../nx-ft/SKILL.md) 的**配套 skill**。nx-ft 负责存储与同源命令，
ft-svg 负责 SVG 这件事本身的标准：**怎么画、怎么判、怎么批量修**。

> 它只管**一套东西**：让一组 SVG 放在一起时「看起来是一家人」——
> 共享同一套坐标、同一套线条、同一种取色方式。这三样一旦分叉，
> 单看每一个都漂亮，摆在一起就是散的。
>
> 注意：**这里的 SVG 不一定是图标**。图标是当前最常用的场景，
> 插画、品牌标也放这儿——它们的取色规则不同（见下方档位）。

## 核心不变量（三条）

| 保证 | 判据 | 谁来管 |
| --- | --- | --- |
| 一套坐标 | `viewBox="0 0 24 24"`，不写死 `width`/`height` | `svg spec check` / `spec fix` |
| 一套线条 | `stroke-width="1.8"`（内容有缩放时按倍数折算）+ `linecap/linejoin="round"` | 同上 |
| 一色跟随主题 | 至少一处 `currentColor`，颜色由外层 CSS 驱动 | 同上 |

**「一色」有三种合法形态**，按档位走（`line` / `duotone` / `color`）；
「放哪都自动正确」这句**只对单色档成立**——双色图标的点缀色、插画的整身配色
都不该被主题色替换。判据与理由见 [[B01-图标]]，档位常量见 [[A02-内置变量与函数]]。

## 60 秒上手

合规骨架（单色图标，只改 `<title>` 与 `d`）：

```html
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none"
     stroke="currentColor" stroke-width="1.8"
     stroke-linecap="round" stroke-linejoin="round">
  <title>加号</title>
  <path d="M12 5v14M5 12h14"/>
</svg>
```

最常用的两条命令：

```bash
node bin/ft.mjs svg spec show                 # 打印规范与骨架（写新图标前先看它）
node bin/ft.mjs svg spec fix <组> --dry-run   # 先看要改什么，确认后再去掉 --dry-run
```

命令、参数与 flag 的**权威清单**看 `node bin/ft.mjs routes --json`，不要凭记忆杜撰。
多行内容走 heredoc 的写法见 [[A01-工作流]]。加 `--json` 得机器可读输出。

## 什么时候**不**触发本 skill

- 只是**管理文件**（建目录、改名、删资源、打标签）→ 那是 nx-ft 的存储层，看 [`nx-ft`](../nx-ft/SKILL.md)
- 要改**这个项目的代码**（新增 action / 改 lint / 加 ref）→ 那是仓库开发，看项目 `README.md`
- 用户要的是**位图**（PNG/JPG）或**字体文件** → 本 skill 只管 SVG
