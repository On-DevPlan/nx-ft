# ft-svg skill：SVG 资源的规范与协作层

这是 [`nx-ft`](../nx-ft/SKILL.md) 的**配套 skill**。nx-ft 负责存储与同源命令，
ft-svg 负责 SVG 这件事本身的标准：**怎么画、怎么判、怎么批量修**。

> **主文档不含任何几何 / 颜色的具体数值**——那些是**各类别自己的约束**。
> SVG 不只放图标：带动画的图形、插画、品牌标**套上图标那套判据只会被改坏**
> （动画的关键帧与线宽都是内容的一部分）。
> **约束跟着类别走，不跟着模块走。**
>
> 所以本 skill 的第一件事是**判断这是哪一类**（下节），再去读那一类的要求。

## 先判类别（这一步别跳）

| 类别 | 该满足什么 | 读哪篇 |
| --- | --- | --- |
| **图标**（线性 / 双色 / 纯配色） | 网格、线宽、端点、取色档位——**全部判据都在那一篇里** | [[B01-图标]] |
| 画**一组**图标 | B01 的判据 + 成套方法（网格与关键线、光学对齐、笔画词汇） | [[B02-图标成套方法]] |
| 插画 / 品牌标 / **带动画的图形** / 其它 | **不套图标那套**：配色与几何由内容自己决定，只走几何容器（viewBox / 尺寸） | [[A00-序列总览]] 的「新增一个场景时」 |

> 判据落在**取色档位**上（`line` / `duotone` / `color`）：
> 哪一部分颜色属于主题、哪一部分属于内容。想不清楚时宁可先用 `color` 档（不改色）。
> 档位常量与函数见 [[A02-内置变量与函数]]。

## 60 秒上手

```bash
node bin/ft.mjs svg spec show                 # 打印规范与骨架（写新图标前先看它）
node bin/ft.mjs svg spec fix <组> --dry-run   # 先看要改什么，确认后再去掉 --dry-run
node bin/ft.mjs svg board                     # 整库状态：哪些待规范
```

命令、参数与 flag 的**权威清单**看 `node bin/ft.mjs routes --json`，不要凭记忆杜撰。
合规骨架（合规的 `<svg>` 长什么样）见 [[B01-图标]]；多行内容走 heredoc 的写法见 [[A01-工作流]]。
加 `--json` 得机器可读输出。

## 什么时候**不**触发本 skill

- 只是**管理文件**（建目录、改名、删资源、打标签）→ 那是 nx-ft 的存储层，看 [`nx-ft`](../nx-ft/SKILL.md)
- 要改**这个项目的代码**（新增 action / 改 lint / 加 ref）→ 那是仓库开发，看项目 `README.md`
- 用户要的是**位图**（PNG/JPG）或**字体文件** → 本 skill 只管 SVG
