# 20 · 图标集方法论：怎么让一组图标「看起来齐」

> [10-icon-spec.md](10-icon-spec.md) 解决的是「三者一致」（网格 / 线宽 / 取色），
> 那是**机器可校验**的部分。这份文档解决剩下的一半：几何落点、视觉重量、
> 笔画词汇——这些 `spec check` 判不了，但正是「一看就是一套」和
> 「像从三个库里各捡了几个」的差别。

## 1. 网格与关键线

24×24 画布，四周留 2pt 安全边距 → **活动区 20×20**（`x, y ∈ [2, 22]`）。

在这个活动区里，不同外形的「标准尺寸」不一样。这不是随心所欲，而是**光学补偿**：
同样高度的圆和方，圆看起来会比方小，所以圆必须比方形关键线大一点。

| 外形 | 关键线 | 坐标 | 说明 |
| --- | --- | --- | --- |
| 方形 | 18×18 | `3 → 21` | 直线图形的最大边界 |
| 圆形 / 曲线 | Ø 20（`r = 10`） | 圆心 `12,12` | 曲线要溢出方形关键线，视觉上才等大 |
| 竖向矩形 | 16×20 | `x: 4→20, y: 2→22` | 如手机、文档 |
| 横向矩形 | 20×16 | `x: 2→22, y: 4→20` | 如显示器、卡片 |

描边会向外扩 `strokeWidth / 2 = 0.9`，所以方形关键线实际绘制范围是 `2.1 → 21.9`，
仍然落在活动区内。**如果某个图形画到了 `x = 22.9`，它就已经出界了**——
虽然不会报错，但和其它图标排在一起时它会显得更大。

参考形状（直接抄尺寸，不要凭感觉）：

```html
<!-- 方形关键线 -->
<rect x="3" y="3" width="18" height="18" rx="2"/>
<!-- 圆形关键线 -->
<circle cx="12" cy="12" r="10"/>
<!-- 竖向矩形：手机 -->
<rect x="4" y="2" width="16" height="20" rx="2"/>
<!-- 横向矩形：显示器 -->
<rect x="2" y="4" width="20" height="16" rx="2"/>
<!-- 搜索：圆 + 手柄，圆心略偏左上，手柄走 45° 到活动区角 -->
<circle cx="10.5" cy="10.5" r="6.5"/><path d="M15.2 15.2 20 20"/>
```

## 2. 坐标落点

- **整数或 `.5`**。24pt 网格不需要更细的刻度；`.25` 这种精度在 16px 渲染下是随机像素。
- **45° 斜线必须 `dx === dy`**。`M15.2 15.2 20 20` 是 45°；`M15.2 15.2 20 19.6` 不是，
  看起来会「歪一下」，而单看又说不清哪里不对。
- **端点之间至少留 1.5pt**。圆线帽会向两端各扩 0.9pt，间距 1pt 时两个端点会视觉粘在一起。
- **轴对齐的线走整格**：`M12 5v14` 而不是 `M12 5.3v13.6`。

## 3. 视觉重心（optical centering）

几何居中的几何图形，看起来往往不居中。常见修正：

| 图形 | 修正 |
| --- | --- |
| 三角形（如播放键） | 向右移约 0.5pt —— 三角形的视觉重心偏左 |
| 上尖下宽的图形 | 上移约 0.25pt |
| 带手柄的圆（放大镜） | 圆心移到 `10.5, 10.5`，手柄占右下，整体重心回正 |
| 圆形 | 顶部顶点超出方形关键线约 0.5pt（overshoot） |

改完把图标缩到 16px、和相邻图标并排看一眼——目光落在哪个上，就调哪个。

## 4. 笔画词汇

一整套图标共享同一套「笔画语言」。**选定后不要中途换**：

| 词汇 | 取值 | 用途 |
| --- | --- | --- |
| 圆角半径 | `0` / `2` / `4` 三档选一 | 一套里混用 2 和 4 会显得两个库拼起来 |
| 线帽 / 连接 | 固定 `round` | 规范强制，见 10-icon-spec |
| 图元间隙 | `2` 或 `3` | 一致的呼吸感；`M12 8v3M12 13v3` 这种 gap 也是 2 |
| 斜线角度 | 45° | 同组里出现 30°/45° 混用，会显得手绘而非设计 |

一个具体例子——「删除」图标的间隙：

```html
<!-- 桶身与桶盖之间留 1.5，桶内两条竖线各自距边缘 1，中间 gap 4 -->
<path d="M9.5 4.5h5v2.5h-5z"/>
<path d="M4.5 7h15"/>
<path d="M6.5 7l1 13h9l1-13"/>
```

不要求这些数字唯一正确，要求的是**同组里所有图标的对应部位用同一个数字**。

## 5. 复杂度预算

一组图标摆在一起时，「墨水量」不均比造型不美更显眼。

- **单枚 1–3 个图元**。超过 4 个通常意味着该拆成两个图标，或者该做减法。
- **总路径长度相差不超过约 1.5 倍**。一组的平均路径长度是 40，突然来一个 120 的，
  它会在视觉上「更重」。
- **实心面积占比一致**。全线性组里混一个 `fill` 实心图标，会被误认为是「选中态」而非一个图标。

## 6. 命名与分组

**分组**（1~3 段路径）按用途而非外形：

| 分组 | 收什么 |
| --- | --- |
| `ui/nav` | 导航：home / search / user / settings / menu |
| `ui/action` | 操作：plus / check / trash / download / edit / filter |
| `ui/status` | 状态：info / warning / error / success / empty |
| `ui/file` | 文件类型：file / folder / image / code |
| `logo` | 品牌标识（不自成一套规范，单独放） |

**资源名**用 kebab-case，前缀表方向、后缀表变体：

```
arrow-up      arrow-down    chevron-left   chevron-right
plus          minus         check          close
trash         trash-2       edit           save
```

避免 `icon-arrow-up` 这种冗余前缀（分组已经说明了它是图标）；
避免 `ArrowUp`（大小写在不同文件系统上会撞名）。

**展示名**写 `<title>`，用最短的中文词：`加号` / `删除` / `向右`。
它会被 `svg import --label-from title` 直接取用，也是看板上显示的字。

**标签**用于筛选，建议三轴：

- 风格族：`outline` / `filled` / `duotone`
- 用途：`nav` / `action` / `form`
- 状态：`legacy`（待替换）/ `beta`

## 7. 交付前评审清单

机器能查的（必须全绿）：

```bash
node bin/ft.mjs svg spec check <组>          # 待规范 0
node bin/ft.mjs svg spec fix <组> --dry-run  # 改动 0 个
```

机器查不了的（**每次都要人眼过**）：

1. **缩到 16px** 看一眼：有没有笔画糊成一团、细部直接消失的
2. **排成一行**：有没有某一枚明显更大 / 更粗 / 更满 / 更空
3. **反转底色**（面板整页预览切「深色」）：是不是都跟着变色了
4. **一秒测试**：遮住名字，能不能在 1 秒内认出这是什么
5. **同类测试**：把 `plus` / `close` / `minus` 放一起——它们的笔画粗细、端点处理、尺寸是否完全一致

第 5 条是最容易漏也最致命的一条：单独看都合格，并排看才发现一个「十」是 14pt、
另一个是 13pt。面板的看板页就是为这一条做的——把它当尺子用。
