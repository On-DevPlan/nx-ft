# A02 · 内置变量与函数

> 这套规范不是「文档约定」而是**可执行的代码**：常量、审计、归一化都在
> `src/core/svg/spec.js` 里各有一份唯一定义。这份文档是它们的人读索引——
> 什么时候读它：要写代码调用、要判断某个行为是不是符合规范、
> 或者发现「审计说的和归一化做的不一致」时来对账。

## 为什么这些必须是纯函数

面板要对上百个图标实时审计，CLI 要能批量跑，**两边必须得出完全一样的结果**。
所以它们放在 `core/`（无业务语义、无 IO），只吃字符串、只吐数据结构。
任何"带 IO 的校验"都会让面板与 CLI 分叉——那是这套体系最容易崩的地方。

## ICON_SPEC：**图标档**的常量

> 这套常量只服务「图标」这一类（判据与理由见 [[B01-图标]]）。
> 别的类别不套它——插画 / 品牌标 / 带动画的图形走 `color` 档，
> 只统一几何容器，不碰颜色与线宽。

```js
export const ICON_SPEC = {
  viewBox: '0 0 24 24',   // 一套坐标
  grid: 24,               // 网格（人读用，审计不直接比对）
  strokeWidth: 1.8,       // 一套线条
  strokeLinecap: 'round',
  strokeLinejoin: 'round',
  color: 'currentColor',  // 一种取色（主题色走它）
};
```

判据的**理由**（为什么是 24 / 1.8 / round）见 [[B01-图标]]，这里是取值本身。

## PROFILES：归一化档位

```js
export const PROFILES = ['auto', 'line', 'duotone', 'color'];
```

| 档位 | 取色规则 | 其它 | 适用 |
| --- | --- | --- | --- |
| `auto`（**默认**） | 由 `detectProfile` 按形态决定 | — | 一切：不套图标尺子去量动画/插画 |
| `line` | **全部**颜色 → `currentColor` | 补 `fill=none` / 根 `stroke` / 线宽 / 线帽 | 单色线性图标 |
| `duotone` | **只有 `--accent` 指定的那一色** → `currentColor`，其余保留 | 不强制根 `fill`/`stroke`（填充式图标会被多描一圈） | 双色图标：一色跟主题、一色是设计色 |
| `color` | 颜色**全部保留** | **不迁 viewBox、不查线宽**（800×600 是画面尺寸，不是待对齐的网格） | 插画 / 品牌标 / 带动画的图形 |

> **默认是 `auto` 而不是 `line`**——这是一条被真实案例逼出来的默认：
> 一段 800×600 的 SVG 动画用图标尺子量，会报出「viewBox 应为 24 24」
> 「写死的颜色应改 currentColor」「线宽应统一为 1.8」，条条都改不掉也不该改。
> 想按图标规格要求它，**显式传 `--profile line`**——那是「我要它当图标」的表达。

## 函数清单

| 函数 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `parseSvg(code)` | svg 字符串 | `{ok, error?, viewBox, hasSize, colors[], strokeWidths[], stats, root}` | 结构提取；解析不了就 `ok:false`，**不猜** |
| `auditSvg(code, {spec?, profile?, accent?})` | + 档位 | `{ok, issues[], meta}` | issues 每项 `{level, code, message, hint}`；`level: 'error'` 才阻断 |
| `normalizeSvg(code, {spec?, profile?, accent?})` | + 档位 | `{ok, code, changed[], error?}` | 返回改写后的代码 + 逐条改动说明（面板直接展示这几行） |
| `detectProfile(src)` | svg 字符串 | `'line' \| 'duotone' \| 'color'` | 按实际形态自动判档：**含 SMIL / `<script>` 动画 = `color`**（图标那套会把动画改坏）；有主题色且还有点缀色 = 双色；只有写死色 = 纯配色；否则单色 |
| `collectColors(src)` | svg 字符串 | 写死的颜色数组 | 排除 `none` / `currentColor` / `url(#…)` / `var(…)` |
| `collectStrokeWidths(src)` | svg 字符串 | 线宽数组（全文档） | 含子图元与内联 style |
| `parseViewBox(str)` / `wrapScaleOf(src)` | — | — | 解析 viewBox；读出内容包裹层的 `scale(k)` |
| `ICON_SKELETON` | 常量 | 合规骨架字符串 | `svg spec show` 直接吐它给 agent 照抄 |

## 三条「判据必须只此一处」

这三处曾经各写一份，结果两两打架。改动时**先想清楚是改判据还是改实现**：

1. **审计与归一化共用同一判据**。例：根元素 `fill` 是否该报「非 none」，
   两边都跳过 `var(…)` 引用——否则会出现「审计说合规、归一化却把它改掉」。
2. **线宽按「属性值 × 内容缩放」判定**。归一化把 32pt 网格迁到 24pt 时，
   内容被包进 `<g transform="scale(0.75)">`，**缩放同样作用在线宽上**：
   里面写 `2.4`、渲染出来才是规范的 `1.8`。
   `wrapScaleOf` 就是为这条服务的——漏了它会出现「审计说 1.8 合规、
   实际渲染 1.35」（真实踩过：29 枚图标线宽偏细却全部报合规）。
3. **档位判定自动化**（`detectProfile`）。看板不要求用户指定档位；
   一枚图标是不是双色，看它有没有「主题色 + 点缀色」就知道了。

## 渲染侧的安全边界

面板把图标**内联渲染**进页面（不是每个都开 iframe），所以走
`dangerouslySetInnerHTML`，必须先消毒：前端 `svg-inline.jsx` 的 `safeSvg()`
定点剥离 `<script>` / `<foreignObject>` / `on*` 事件 / `javascript:` 链接。

这是**定点剥离**而不是完整解析：图标源码来自本机资源库，但 `svg import`
可以指向任意目录（比如一个下载文件夹）。完整解析器会误伤合法路径，得不偿失——
但**不要**因为「反正是本机文件」就跳过这一步。

## 命令面入口

| 命令 | 关键 flag | 说明 |
| --- | --- | --- |
| `svg spec show` | — | 打印规范 + 档位 + 合规骨架（agent 写新图标前先看它） |
| `svg spec check [组]` | `--profile`（默认 `auto`） `--accent` | 不传分组 = 整库；逐条列出问题 |
| `svg spec fix [组]` | `--profile` `--accent` `--style` `--dry-run` | 不传分组 = 整库；只修「当前风格」或 `--style` 指定的那个 |

> `--profile duotone` 必须配 `--accent "#RRGGBB"`——不指定主题色，
> 工具无从判断该把哪一色换成 `currentColor`，会直接报错而不是猜。
> 反过来，`auto` 判出双色但没给 `accent` 时**不动颜色**：猜就是破坏。

面板侧的两视图（编辑 / 画廊）与批量动作见 [[A01-工作流]]。
