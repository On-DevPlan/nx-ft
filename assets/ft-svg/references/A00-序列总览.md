# A00 · 序列总览与路由

> ft-svg 的 reference 分两个序列。**先读这里**，再按需进入具体 ref。
>
> 两句话就能记住分工：
> **A 序列 = 怎么用**（工作流、内置变量与函数）；
> **B 序列 = 画什么**（不同类别的 SVG 各自该满足什么）。

## 序列划分

| 代号 | 类别 | 回答的问题 | 成员 |
| --- | --- | --- | --- |
| **A** | 工作流与实现 | 「这套东西怎么跑起来、有哪些变量和函数可用」 | [[A01-工作流]] / [[A02-内置变量与函数]] |
| **B** | SVG 场景 | 「这一类 SVG 该长什么样、怎么算合格」 | [[B01-图标]] / [[B02-图标成套方法]] |

> 两个序列的**读者不同**：A 序列是"我要动手改 / 跑批"，B 序列是"我要画 / 我要判"。
> 绝大多数任务只需要其中一个序列——这就是分成两个序列的判据
> （见 key_board 的「按读者划分，不按主题词划分」）。

### 新增一个场景时

B 序列是**按场景生长**的：图标只是第一种。以后遇到别的 SVG 类别，
新建 `B0X-<场景>.md` + 在主 SKILL.md 的路由表加一行即可，**不要**往 B01 里塞
（B01 只回答"图标"这一件事）。已知的候选场景与它们的档位倾向：

| 候选场景 | 档位倾向 | 与图标的差别 |
| --- | --- | --- |
| 插画 / 示意图 | `color`（保留自带配色） | 配色就是内容，不该被主题色替换 |
| 品牌标 / logo | `color` 或 `duotone` | 主色是品牌资产，通常固定；辅助形可跟主题 |
| 线性图标 | `line` 或 `duotone` | 就是 B01 覆盖的范围 |

> 判据落在**取色档位**上（见 [[A02-内置变量与函数]] 的 `PROFILES`）：
> 「这一部分颜色属于主题，还是属于内容？」——属于主题的换成 `currentColor`，
> 属于内容的原样保留。想不清楚时宁可先用 `color` 档（不改色），
> 强行统一会把设计意图抹掉。
