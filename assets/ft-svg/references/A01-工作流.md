# A01 · 工作流

> 面板是「可视化验证」的入口，不是另一套系统：**面板上每个按钮都有一条同构的 CLI 命令**，
> 底部提示块会把它列出来。这份文档说明看板怎么读、批量动作怎么做、
> 以及出错时先看哪里。

## 1. 路由（可分享、可后退）

| 路由 | 页面 |
| --- | --- |
| `#/svg` | 根目录（网盘页）：面包屑 + 内联新建 + 当前层的文件夹与图标 |
| `#/svg/dir/<组路径>` | 进入某个文件夹：只显示这一层的内容 |
| `#/svg/edit/<组路径>/<名>` | 资源页：一枚图标的全部风格 + 编辑器 + 规范问题 |
| `#/svg/edit/<组路径>/<名>/full` | 整页预览：放大看线帽、拐点、网格 |

分组路径里的斜杠照常写：`#/svg/dir/ui/icons/nav`。解析规则是
「首段是类型标记，末段是资源名，中间剩下的拼回分组路径」，
所以 URL 一直是可读的，也能直接贴给别人。浏览器后退键天然可用。

### 用户贴链接说「加图标」时

**先解码出意图，别反问是哪个分组**：

> 用户：给 `http://127.0.0.1:7869/#/svg/dir/%E6%B5%8B%E8%AF%95` 添加资源

读出四件事：模块 = **svg**（首段）；操作 = 进入某个目录（`dir` 段）；
分组 = **测试**（`%E6%B5%8B%E8%AF%95` 解码后是「测试」）；该做什么 = 在「测试」里**新建资源**。

```bash
nx-ft svg add 测试 <资源名> --style default
```

链接落在 `edit/<组>/<名>` 上时语义不同——那是「**改这一枚**」：
改代码走 `svg put <组> <名> --style <风格> --code -`，改展示名走 `svg rename`。
口诀：**`dir` = 往这个文件夹放东西；`edit` = 改这一个。**

## 2. 网盘页怎么读

页面就是**当前文件夹**的内容，层级靠「点文件夹卡片下行、点面包屑回跳」——
没有左侧常驻目录树。

```
标题行      SVG 资源 · 2 个分组 · 48 个资源          [搜索____]  [编辑|画廊]
看板动作    [批量导入][批量导出][规范自检][一键归一化]
地址栏      全部 / fr
内联新建    [+ 新建文件夹]  [+ 新建资源]
文件夹      fr(48) …
```

创建一律是**内联输入行**（点「+ 新建」→ 原位出现输入框 → 回车即建）：
只问名字。展示名、标签、描述都是**建完再补的元数据**，不在创建路径上拦人。
根目录也能直接建图标——会自动落进「未分类」文件夹。

## 2.1 两个视图：编辑 / 画廊

标题行右侧切换，选择会被记住。

| 视图 | 看什么 | 什么时候用 |
| --- | --- | --- |
| **编辑** | 文件夹 + 资源卡片（名字、标签、风格数） | 改名、删、打标签、看元信息 |
| **画廊** | 当前文件夹的图标平铺成墙，配**主题色范围** | 快速浏览一批图标、验证「跟着主题色变」的效果 |

画廊的三个旋钮：

- **主题色**：八个标准色一键切（正文黑/次要灰/主色绿/链接蓝/警示橙/危险红/紫/白），
  另有一个自定义取色器。切一次，**整墙图标同时变色**——哪一枚没跟随
  （漏了 `currentColor`）当场显形。白底那把会同时把墙换成深底，用来核对深色场景。
  色值范围与理由见 [B01-图标.md](B01-图标.md) 的「颜色范围」。
- **尺寸**：20 / 24 / 32 / 48。小尺寸最先暴露细笔画糊成一团的问题。
- **含子文件夹**：把这一支下面所有层级的图标一起铺上来（默认只当前层）。

> 画廊不改变任何数据，是纯读视图：点任意一枚进资源页继续编辑。
> 「统一管控一批外部图标」的标准路径是：`svg import` 导入 → `svg spec check`
> 看违规 → `svg spec fix` 归一化（颜色强制回 `currentColor`）→ 画廊切色验证。

## 2.2 规范状态怎么读

| 标记 | 含义 |
| --- | --- |
| 不挂角标 | 合规。**合规不标注**——48 枚全标「合规」是没有信息量的噪音 |
| 角标（待规范） | 这一枚的 `activeStyle` 有规范问题，点进去看具体条目 |
| 脚注 `×N` | 这一枚有 N 个风格（多版本并存），不是异常 |

- **「待规范」用墨色而不是红色**：它表示「需要看一眼」，不是错误。
  真正阻断的问题（无根元素 / 空图形）才会用 `--bad`。
- **待规范 = 当前风格不合规**。一个资源有多个风格时，规范检查只看 `activeStyle`。
  所以会出现「列表标着待规范，点进去发现这一版合规」——那是你正在编辑的风格
  不是当前风格。`svg style switch <组> <名> <风格>` 可以改当前风格。

## 3. 资源页

从上到下五块：

1. **面包屑 + 动作条**：整页预览 / 编辑历史 / 按规范修复 / 保存（有未保存改动时显示 `保存 *`）
2. **身份卡**：图形、展示名、路径、标签、风格数、整体合规状态
3. **风格对比**：所有风格并排，各自显示图形 + 合规状态 + 历史条数。
   边框加重的那张是**当前编辑目标**（点一下即切换）；标着「当前」的是**当前风格**（面板与看板默认展示它）
4. **编辑器 + 实时预览 + 规范问题**：三槽位（SVG / CSS / JS），`Ctrl/Cmd+S` 保存；
   右侧实时预览按 62% 居中渲染，规范问题逐条列出并给出修法
5. **CLI 命令块**：这一枚图标对应的 `cat` / `put` / `spec check` / `spec fix` / `detail`
   五条命令，参数已经填好，可直接复制执行；下面还有一段 `<<'EOF'` 的写回模板

「风格」和「当前风格」的区别值得再强调一次：

- **风格**（style）＝ 同一枚图标的并存实现，用于 A/B 对比，数量不限
- **当前风格**（activeStyle）＝ 看板与默认预览展示哪一个

## 4. 整页预览

`#/svg/asset/<组>/<名>/full`，或资源页点「整页预览」，或看板图标格右上角悬停出现的「全页」。

- **尺寸阶梯** 24 / 32 / 48 / 96 / 192 / 384 —— 24 是设计尺寸，16 是常见渲染尺寸，
  384 用来看清曲线拐点
- **底色** 白底 / 浅灰 / 深色 —— 切到深色是为了验证 `currentColor` 真的生效：
  如果某个图标在深色底上没变白，说明它写了死颜色（`spec check` 也会报 `hardcoded-color`）
- **24pt 网格** 叠加每格 1pt 的参考线 —— 用来核对关键线：方形应落在 `3→21`，
  圆形 `r=10`，坐标应落在整数或 `.5`
- **复制源码** 一键拿走当前风格的 SVG 本体

## 5. 批量导入

```bash
nx-ft svg import <组> --from <目录> [--style default] [--tags a,b] \
    [--recursive] [--label-from filename|title] [--dry-run]
```

面板上的「批量导入」是同一个流程的两段式：**先填目录 → 再填目标分组 → 看计划 → 确认**。

行为要点：

| 项 | 行为 |
| --- | --- |
| 分组不存在 | 自动创建（报告里会写「分组为本次新建」） |
| 展示名来源 | `--label-from title`（默认）= 取 SVG 里的 `<title>`，取不到退回文件名；`filename` = 直接用文件名 |
| 资源名来源 | 文件名去扩展名，非法字符替换为 `-`（不追求好看的 slug，只求稳定寻址） |
| 已存在同名资源 | **跳过**并如实上报，不覆盖 |
| 目录里派生出的重名 | 导入前就整批拒绝（大小写不敏感的文件系统上很常见），不会静默丢文件 |
| 子目录 | 默认不加 `--recursive` 只扫一层 |

**导入是逐字节搬迁，不改内容。** 要改内容请用 `svg spec fix`——
那是显式的、会进编辑历史的动作；transfer 只搬不改，否则「导出再导入」就不是恒等变换了。

## 6. 批量导出

```bash
nx-ft svg export [<组>] --to <目录> [--style <风格>] [--board] [--force]
```

产出「目录 + 一张自包含的 `index.html` 看板页」——图标按分组落到子目录，
`index.html` 把整组内联渲染出来，没有任何外部依赖，可以直接打包交接或丢进浏览器看。

| 项 | 行为 |
| --- | --- |
| 不传 `<组>` | 导出整库 |
| 不传 `--style` | 各资源各取当前风格 |
| 同名文件 | **默认跳过**并列出（导出器不改写别人的文件），`--force` 才覆盖 |
| 风格 svg 槽位为空 | 跳过并写明原因 |
| `--board` | 默认开；`--board=false` 只出 `.svg` |

## 7. 规范审计与归一化

```bash
nx-ft svg spec show                 # 规范全文 + 合规骨架
nx-ft svg spec check [<组>]         # 逐条列出不合规的图标与原因
nx-ft svg spec fix [<组>] --dry-run # 先看改动清单
nx-ft svg spec fix [<组>]           # 确认后写回
```

`<组>` 可省略 = 整库（`check` 与 `fix` 一致）。

**档位默认 `auto`（按资源形态自动判）**，所以这两条命令**不会**拿图标尺子去量
插画和动画——那会报出一串「viewBox 应为 24 24 / 颜色应改 currentColor / 线宽应统一为 1.8」
之类改不掉也不该改的问题。想按图标规格要求某组资源，**显式传 `--profile line`**：

```bash
nx-ft svg spec check 测试                  # 动画/插画：通常「待规范 0」
nx-ft svg spec check 测试 --profile line   # 我要它当图标 → 才用图标尺子
```

面板上是「规范自检」（弹窗列出每条问题）与「一键归一化」（先弹计划确认框，
确认后才写回，完成后给结果面板）。**两段式不是多余的谨慎**：
批量改上百个图标是不可逆操作，而 `spec fix` 会占掉编辑历史的名额。

`spec fix` 的三条边界，遇到时不要当成 bug：

1. **长宽比不一致就拒绝迁移** `viewBox`，并保留原值 + 说明原因（强行等比缩放会把图形压扁）
2. **阻断级问题（`no-root` / `empty`）修不了**，会进 `failed` 列表而不是静默跳过
3. **只修「当前风格」或 `--style` 指定的那一个**，不提供「全库所有风格」——
   那等于把一套设计稿里刻意保留的对比版本一起抹平

## 8. 失败排查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 导入报「目录不存在或不可读」 | 路径写错，或不是本机可达路径 | 用绝对路径；确认目录里有 `.svg` |
| 导入报「多个文件派生出同名资源」 | `Foo.svg` 与 `foo.svg` 在 Windows/macOS 上会撞 | 改名后重导 |
| 导入后展示名是文件名不是中文 | 没加 `--label-from title`，或 SVG 里没有 `<title>` | 补 `<title>` 再导，或导入后 `svg rename` |
| 导出报告「跳过：文件已存在」 | 目标目录有旧文件 | 换个新目录，或 `--force` |
| 导出报告「跳过：风格 X 的 svg 槽位为空」 | 该资源还没写代码 | 先 `svg put` 写内容 |
| 看板标「待规范」，资源页说合规 | 看板审计的是**当前风格** | `svg style switch` 切到那个风格 |
| `spec fix` 报「viewBox 保持…（长宽比不一致）」 | 图形不是正方形（如 `0 0 32 16`） | 需人工决定：重画成方形，或接受不合规 |
| `spec fix` 的 `failed` 里有条目 | 阻断级问题：没有根元素 / 没有图元 | 补图形，自动修不了 |
| 面板改完，CLI `cat` 读到的还是旧的 | 面板的改动**只在点保存后**落盘 | 点保存（或 `Ctrl/Cmd+S`） |
| 面板看到的内容和 `cat` 不一致 | 两边看的是不同风格 | 资源页顶部的风格对比里确认当前编辑的是哪个 |

## 9. 面板与 CLI 的等价关系

不需要背两套东西。规则只有一条：**面板上能做的每个动作，都有一条同构的 CLI 命令**
（同一个 action 声明同时派生 CLI 命令与 HTTP 路由，由结构保证，不靠人记）。

**面板上不显示 CLI 命令**——那是刻意的：面向使用者的界面不该被命令文本占掉注意力，
真要用命令的人直接看 `routes`：

- 全量对照表（CLI ↔ HTTP）：`nx-ft routes`
- 机器可读（agent 直接消费）：`nx-ft routes --json`

给 agent 派活时，**在提示里把完整命令写给它**（组、名、风格、`--code -` 都填好），
比让它自己拼 `svg put <组> <名> --style <风格> --code -` 可靠得多。
