# A02 · 内置变量与函数

> 这份文档回答「**内部规则是什么**」：槽位怎么定义、预览外壳怎么组装、
> 历史留几条、标签与命名受什么约束。动手流程本身见 [[A01-工作流]]。
>
> 这些规则都定义在 `src/core/assets/` 与前端 `asset/preview.jsx`，
> 面板与 CLI **共用同一份**——所以面板上看到的行为就是 CLI 的行为，不会分叉。

## ASSET_KINDS：槽位定义

```js
export const ASSET_KINDS = {
  html: { label: 'HTML 资源', slots: ['html', 'css', 'js'] },
  svg:  { label: 'SVG 资源',  slots: ['svg',  'css', 'js'] },
};
```

- **槽位顺序即面板编辑框的展示顺序**（工作台里从左到右）。
- 槽位 ↔ flag 的映射：`html` → `--code-html`、`css` → `--code-css`、`js` → `--code-js`；
  HTTP body 用**短键**：`{ group, name, style, html, css, js }`。
- 写错槽位名会被明确拒绝（`未知代码槽位`），不会静默丢弃。

## HISTORY_KEEP = 5：编辑历史

每次 `put`/保存都把**改动前**的状态推进该风格的 `history/`，**每风格滚动保留最近 5 条**，
第 6 次保存淘汰最旧的一条。所以：

- 改坏了能退回（`html history restore … --entry <id>`）。
- 但**改超过 5 次就回不到最初**——需要保留的版本应另开一个**风格**，不是靠历史。

## 预览外壳：`buildHtmlDoc` 的真实规则

预览不是「原样塞进 iframe」——资源代码要先组装成一份完整文档：

| 你写的内容 | 预览怎么处理 |
| --- | --- |
| **没有** `<html>` 的片段 | 补一整套壳：`<!doctype html>` + `<meta charset>` + 居中样式（`body{display:grid;place-items:center;min-height:100vh}`），再把 `<style>`（CSS 槽位）注入 `<head>`、`<script>`（JS 槽位）注入 `</body>` 前 |
| **有** `<html>` 的完整文档 | 只补缺失的部分：有 `<head>` 就往里插 CSS，有 `</body>` 就往里插 JS；**不覆盖你写的东西** |

这条规则解释了两个最常见的困惑：

- 「我只写了一个 `<button>`，怎么预览里它是居中的」——外层壳给的居中，不是你写的。
- 「我写了完整的 `<html>`，为什么样式没注入」——因为你没有 `</head>`，壳无从插入。

## 命名与标签的约束

| 对象 | 规则 |
| --- | --- |
| 分组路径 | 1~8 段（`ui/buttons/primary`），段名不含 `/` `\` `..`、不以 `.` 开头 |
| 资源名 / 风格名 | 同上（安全名规则），资源名即磁盘目录名，惯例用 kebab-case |
| 展示名 `label` | ≤ 60 字符；不填则等于资源名 |
| 标签 | 归一化为小写（空白转 `-`），可用字母 / 数字 / **汉字** / `-` `_` `.`，≤ 24 字符 |

- **重复添加标签是幂等跳过**（返回 `skipped`），不是错误。
- **删除非空分组 / 资源需要 `--force`**：CLI 会先返回 `blocked` 让调用方决策，
  而不是直接删或直接报错。

## 描述字段的用途

- **风格描述**（`html style desc … --text "深色胶囊"`）：一句话说明这套风格的特征，
  面板风格切换时显示。**它是给人和 agent 检索用的元信息**——同类资源多了以后，
  「哪套是圆角、哪套是方形」靠名字看不出来，靠描述。
- **资源展示名**：面向人的名字（`label`），与磁盘目录名（`name`）解耦——
  改名不改路径，引用不会断。
