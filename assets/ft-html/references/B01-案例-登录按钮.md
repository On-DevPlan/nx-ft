# B01 · 案例：一个场景 + 多套风格

> 最常用的套路：**同一个场景（登录按钮）并存几套做法**，横向对比再定稿。
> 规则细节（槽位定义、历史条数、预览外壳）见 A 序列，这里只走一遍完整过程。

## 为什么是这个案例

「同一件事有几种做法」是这个工具存在的理由。如果只做一套，用任何编辑器都比它快；
它的价值在于：**让三套实现同时可见、可切换、可回退**，比较完再决定用哪套。

## 完整过程

```bash
# 1) 建分组（想多层就写 ui/buttons/primary，1~8 段）
node bin/ft.mjs html group add ui/buttons --label 按钮

# 2) 建场景 + 第一套风格。标签是 100+ 资源时的检索入口，建的时候就打上
node bin/ft.mjs html add ui/buttons login-btn --label 登录按钮 --style minimal --tags button,login

# 3) 写三个槽位：结构 / 外观 / 行为，各写各的
node bin/ft.mjs html put ui/buttons login-btn --style minimal --code-html - <<'EOF'
<button class="btn" type="button">登录</button>
EOF

node bin/ft.mjs html put ui/buttons login-btn --style minimal --code-css '.btn{padding:10px 24px;border-radius:6px;border:1px solid #d0d7de;background:#fff}'

# 4) 派生第二套风格：--copy-from 先把现在的代码抄过去，再改差异部分
node bin/ft.mjs html style add ui/buttons login-btn dark --copy-from minimal --desc 深色胶囊
node bin/ft.mjs html put ui/buttons login-btn --style dark --code-css '.btn{padding:10px 24px;border-radius:999px;border:0;background:#14161a;color:#fff}'

# 5) 第三套：只改 CSS 就能做出完全不同的观感，不必重写 HTML
node bin/ft.mjs html style add ui/buttons login-btn glass --copy-from minimal --desc 玻璃拟态
node bin/ft.mjs html put ui/buttons login-btn --style glass --code-css '.btn{padding:10px 24px;border-radius:12px;border:1px solid rgba(255,255,255,.4);backdrop-filter:blur(8px);background:rgba(255,255,255,.2)}'

# 6) 看对比：面板 → HTML 资源 → ui/buttons → 点 login-btn 卡片
node bin/ft.mjs serve
```

工作台里用右上角的**风格切换**逐个看，预览实时刷新；`activeStyle` 决定默认显示哪套
（`html style switch ui/buttons login-btn dark` 可以改）。

## 什么时候该派生新风格，什么时候该改现有风格

| 情形 | 做法 |
| --- | --- |
| 想**比较**两种做法 | `style add --copy-from`（原样保留，改差异） |
| 想**改**当前这套 | 直接 `put`（改动前进历史，可回退） |
| 改了很多次想找回最早的 | `history` 只留 5 条——**超过就找不回了**，该派生风格时别硬改 |

## 踩过的坑

- **预览默认居中**：只写 `<button>` 时它会在预览里居中，那是预览壳给的（见 [[A02-内置变量与函数]]），
  不是你的 CSS 生效错了。
- **多行 CSS 也走 heredoc**：单行可以直接跟在 flag 后面，多行必须 `--code-css - <<'EOF'`。
- **别绕过 CLI 改磁盘**：直接改 `~/.nx-ft/assets/` 下的文件会跳过历史与清单，
  面板看到的还是旧内容。
