# B02 · 案例：整页演示与交互片段

> 上一个案例（[[B01-案例-登录按钮]]）写的是一个**组件片段**。
> 这个案例写**整页文档**——两者的差别不在"大小"，而在**预览外壳会不会介入**。

## 关键差别：你写不写 `<html>`

预览的组装规则（详见 [[A02-内置变量与函数]]）：

- **不写 `<html>`** → 工具补一整套壳（doctype + meta + 居中样式），CSS/JS 槽位注入进去。
  适合「一个组件 / 一段结构」。
- **写了 `<html>`** → 工具只补**缺失的部分**，不覆盖你写的。
  适合「一整页」「要控制 `<head>`」「要做响应式视口」。

所以：**只有当你要控制文档级的东西，才写完整 `<html>`**；否则片段更省事。

## 完整过程（整页 + 交互）

```bash
node bin/ft.mjs html group add demos --label 演示页
node bin/ft.mjs html add demos counter-card --label 计数器卡片 --style default --tags demo,interactive

# HTML：这次写完整文档（要控制 viewport，让手机上也不缩成一团）
node bin/ft.mjs html put demos counter-card --style default --code-html - <<'EOF'
<!doctype html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>计数器卡片</title>
</head>
<body>
  <div class="card">
    <p class="num" id="num">0</p>
    <div class="acts">
      <button type="button" id="dec">−1</button>
      <button type="button" id="inc">+1</button>
    </div>
  </div>
</body>
</html>
EOF

node bin/ft.mjs html put demos counter-card --style default --code-css '.card{margin:48px auto;width:240px;padding:24px;border:1px solid #d0d7de;border-radius:12px;text-align:center;font:14px/1.5 system-ui}.num{font-size:32px;margin:0 0 12px}.acts{display:flex;gap:8px;justify-content:center}'

# JS 槽位：行为独立成一块。注意 </script> 里不要出现裸的 </script> 字面量
node bin/ft.mjs html put demos counter-card --style default --code-js - <<'EOF'
const num = document.getElementById('num');
let n = 0;
const render = () => { num.textContent = String(n); };
document.getElementById('inc').addEventListener('click', () => { n += 1; render(); });
document.getElementById('dec').addEventListener('click', () => { n -= 1; render(); });
render();
EOF
```

## JS 槽位的三条实践

1. **等 DOM 就绪**：脚本注入在 `</body>` 之前，元素已存在，可以直接 `getElementById`；
   但如果你把脚本写进了 `<head>`（自己写了完整文档），就要自己处理加载时机。
2. **不要用 `alert`/`confirm` 做验证**：预览在 iframe 里，弹窗会打断整体操作；
   把结果写到 DOM 上更直观。
3. **抛错会静默**：JS 报错只在浏览器控制台可见，预览里表现为"没反应"。
   先用最简脚本验证通了，再往上加逻辑。

## 什么时候用哪种

| 你要做的 | 写片段还是整页 | 为什么 |
| --- | --- | --- |
| 一个按钮 / 卡片 / 表单 | 片段 | 壳给的居中与 reset 正好，省事 |
| 一整页布局（含响应式） | 整页 | 要控制 `viewport` / `title` / `head` |
| 要看**嵌在别处**的效果 | 片段 | 片段更接近它在真实页面里被插入的形态 |
| 多风格对比同一段结构 | 片段 | 改 CSS 就能换观感，HTML 不必重写 |
