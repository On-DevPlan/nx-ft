# A02 · 数据契约

每个 color 资源 = 一个调色板（Palette JSON），整段存在 `data` 槽位的文件里
（`~/.nx-ft/assets/groups/color/<组>/assets/<调色板>/styles/<风格>/data`）。

## 顶层结构

```ts
interface Palette {
  name: string;           // 展示名
  harmony: PaletteHarmony | null;
  colors: ColorEntry[];
  sortBy: 'manual' | 'hue' | 'brightness' | 'saturation';
  createdAt: number;      // ms since epoch
  updatedAt: number;
}

interface PaletteHarmony {
  type: HarmonyType;         // 4 选 1
  anchorColorId: string;     // 锚色 id（与 colors[].id 对应）
  autoFill: boolean;         // true：锚色变时自动重派生
}

type HarmonyType =
  | 'triadic'              // 三角
  | 'analogous'            // 类似
  | 'split-complementary'  // 分裂互补
  | 'monochromatic';       // 单色
// 注：v1 起去掉 'complementary'，历史数据 schemaVersion=1.3.0 升级时自动转 triadic

interface ColorEntry {
  id: string;                 // 'c-<timestamp>-<rand>'
  hex: string;                // '#RRGGBB' 大写
  weight: number;             // 0..100
  locked: boolean;            // 锁定不参与自动清理
  note: string;
  tags: string[];
  // 派生色才会带这个字段：(paletteId, rule, slot) 决定槽位身份。
  // 切换规则时复用同一批槽位（就地更新 hex/rule，不新建条目）。
  derivedFrom?: { paletteId: string; rule: HarmonyType; slot: number };
  createdAt: number;
  updatedAt: number;
}
```

## 最小骨架（空调色板）

```json
{
  "name": "主色板",
  "harmony": null,
  "colors": [],
  "sortBy": "manual"
}
```

## 槽位身份（继承关系）

派生色由 `(paletteId, slot)` 锚定身份。切换和声类型时：
- **同数**：复用同 `slot` 的条目，就地更新 `hex` / `rule`（id 不变）。
- **槽位变多**：多出的 slot 创建新条目，追加到 palette 末尾。
- **槽位变少**：多余的 slot、未锁的条目从 `colors` 中清理；锁定的保留等用户解锁。
- **关掉规则**（`harmony: null`，面板里选「无」）：该 palette 的所有未锁派生条目从池里清理。
- **关掉自动重派生**（`autoFill: false`）：**保留**当前派生集（冻结），手工调锚色不再覆盖它；
  但换锚色卡仍会按新锚色重算——派生色恒为 f(锚色, 规则)。

这避免了「切规则就堆出新色」的 UI/UX 缺陷。

## 字段约束

| 字段 | 约束 | 不合规时 |
| --- | --- | --- |
| `name` | 非空字符串 | 面板降级为目录名 |
| `harmony` | null 或完整对象 | null 等价「无派生」 |
| `colors` | ColorEntry 数组 | 不是数组 → 面板按空数组处理 |
| `hex` | `#RRGGBB` 大写；CLI 也接受 `#RGB` / `0xRRGGBB` | 解析失败 → 报错不写入 |
| `derivedFrom.slot` | ≥ 0 整数 | 解析时跳过、视为「孤儿派生」 |
| `weight` | 0..100 | 越界在比例视图里会被夹到边界 |

## 面板对 JSON 错误的处理

工作台（`#/color/edit/<g>/<n>`）打开资源时若 `data` 不是合法 JSON，会：
1. 顶部红色提示「DATA 槽位的 JSON 无法解析：…」
2. 编辑框里仍显示原文，让用户修正
3. 不写回盘上，直到保存的 JSON 能解析

预览在解析失败时回退到「按数据字面显示 swatch」，不报错。

## 与共享存储层的关系

| 概念 | nx-ft 存储 | color 域 |
| --- | --- | --- |
| 资源 | `assets/<调色板>/` | = 一个调色板 |
| 风格 | `styles/<风格>/` | 几乎只用 `default` |
| 槽位 | `styles/<风格>/<slot>` | `data` 一个槽位 |
| 历史 | `styles/<风格>/history/<tag>/` | 自动随 saveCode 写入；每风格 5 条 |
| 分组 | `group.json` | 调色板集 |
