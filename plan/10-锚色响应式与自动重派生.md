# 10 锚色响应式 + 自动重派生（P1）

来源：用户反馈「色彩 studio 面板 锚色还是无法响应式 以及自动变化锚色」。

## 根因（两个症状，一个病根）

`palette.harmony.anchorColorId`（锚色 = 派生色的基准色）过去**只在「点和声规则按钮」那一刻
写一次**，之后再也不动。于是：

| 读锚色的地方 | 读的是 |
| --- | --- |
| 色轮上的派生标记（`ColorWheel` → `HarmonyOverlay`） | **当前选中色** `selected.hex` |
| 列表里的派生色卡（`applyAutoFill`） | **旧锚色** `harmony.anchorColorId` |

两边对不上 → 用户看到的正是「锚色无效 / 不响应」。

### 症状 A：锚色不响应

点规则时锚色 = 当时选中的那张卡；之后用户点另一张色卡，`viewState.selectedColorId` 变了，
`harmony.anchorColorId` 没变 → 换色卡不换基准，派生色永远按旧基准算。

### 症状 B：自动变化锚色（autoFill）形同虚设

`useAutoFillEffect` 的指纹盯的是**锚色那张卡的 hex**，而色轮拖动改的是
**当前选中色那张卡**（`pickWheelCommitMode` 只看 `viewState.selectedColorId`）。
两者不是同一张卡时，锚色 hex 永远不变 → 指纹不变 → `applyAutoFill` 永远不跑 →
「锚色变化自动重派生」勾了也没用。

> 症状 A 让「当前选中色 ≠ 锚色」成了常态，症状 B 因此 100% 触发。

## 修法：锚色就是「当前选中的色卡」

新增纯函数模块 `src/engine/anchor.js`（无 import，可直接被 node 单测加载）：

- `resolveAnchorId(doc)`：**选中色 → 和声锚色 → 首色**（都必须是本板真实存在的色卡）。
- `withAnchor(doc, colorId)`：选中态 + `harmony.anchorColorId` 一起改。
- `withHarmonyRule(doc, type)`：切规则时锚色定到当前选中色卡；`type=null` 清和声。
- `reassignDerivedSlot(doc, old, next)`：拿派生色卡当新锚色时，**旧锚色接手它的派生槽位**
  （否则每换一次锚色就多长一张色卡）。
- `repairAnchor(doc, paletteId)`：锚色指向已删除的卡时兜底重指首色。

各归其位：

| 位置 | 改动 |
| --- | --- |
| `useSelectedColor.select()` | 选中即锚色，并 `applyAutoFill(force)` 整组重派生 |
| `useAutoFillEffect` | 指纹改成盯**真实锚色**（= 色轮正在编辑的那张卡）的 id+hex |
| `pickWheelCommitMode` | 编辑目标 = `resolveAnchorId`，不再退回「首色」 |
| `ColorWheel` 规则键 | 走 `withHarmonyRule`（锚色 = 当前选中色） |
| `PaletteSidebar.removeColor` | 锚色卡被删 → 重新指锚 + 整组重派生；板空则清和声 |
| `PaletteSidebar.setActive` | 切板 → 选中态回落到新板的锚色 |
| `addColorEntryAndSelect` | 板上有和声时新色不抢锚色（免得新建一张色就把派生色整组冲掉） |
| `autoFill` | 锚色是基准色不是派生色 → 摘掉它身上的 `derivedFrom` 角标 |
| `colorStudioStore.load` | 载入时逐板 `repairAnchor`（外部改过 JSON 也不会留悬空锚色） |

### 语义定死（避免「修了又飘」）

- **派生色恒为 f(锚色, 规则)**：换锚色卡 → 一定重派生（派生色卡本来就是派生出来的，
  挂着另一个基准的派生色只会让人以为功能坏了）。
- **autoFill 只管「手工调锚色」**：勾上 → 拖色轮 / 改 HEX 实时重派生；关掉 → 手工调锚色
  不覆盖当前派生集（沿用 0.5.x 定的「冻结当前派生集」语义），但**换锚色卡仍然重派生**。
- **锚色可见**：左侧色卡上打「锚」角标，色轮下方有「锚色 #XXXX」读数——用户能看见它跟着走。

## 踩过的坑（记下来别再踩）

1. **`jsxs()` 的第三个参数是 key，不是 children**。本目录是预编译产物，子节点要写进
   `props.children`；写成 `jsxs(tag, props, [a, b])` 会被当成 key → 整块内容渲染不出来
   （DOM 里是个空 div，肉眼在页面上只看到「少了一行」）。
2. **内置 Browser（右侧 FilePanel）标签页在后台会被冻结**：定时器全停、SPA 拿不到数据也
   刷不了新，看起来像「应用坏了」。真实验证走本机 Chrome headless + CDP 直连。
